# HIVE Workflow

## Purpose

This document defines how work flows through HIVE from project creation to delivery.

---

# Project Lifecycle

Draft
→ Active
→ On Hold (optional)
→ Completed
→ Archived

---

# Task Lifecycle

Backlog
→ To Do
→ In Progress
→ Review
→ Done

Rules:

- Only completed work moves to Done.
- Review is mandatory for work requiring approval.
- Archived tasks are read-only.

---

# Standard Delivery Workflow

1. Create Project
2. Add Team Members
3. Create Tasks
4. Prioritise Backlog
5. Move work into To Do
6. Execute work in Progress
7. Review completed work
8. Mark Done
9. Close Project
10. Archive Project

---

# File Workflow

Upload
→ Organise
→ Reference in Tasks
→ Final Version
→ Archive with Project

---

# Approval Workflow

Task Submitted
→ Reviewer Assigned
→ Approved
or
→ Changes Requested
→ Back to In Progress

---

# Notifications

Generate notifications for:

- Task assignment
- Mentions
- Due today
- Overdue
- Review requested
- Task completed

---

# Guiding Principle

HIVE exists to move work forward. Every workflow should reduce friction, not add bureaucracy.
